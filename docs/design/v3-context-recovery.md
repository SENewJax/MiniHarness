# V3：上下文与恢复

[项目入口](../../README.md) · [架构总览](architecture.md) · [实现与验收](../../references/V3-上下文与恢复实现与验收.md)

V3 在同一 Runtime 中解决两件事：模型输入不能无限增长，任务也不能把宿主重启当作从头开始。目标是保留真实身份、约束、成本和执行事实，在可确认的边界继续。

## 三种数据，不同权威

任务事实和执行记录决定权限、预算、证据、操作和资源状态。原始历史保存可审计内容。模型输入只是这两类数据的一个可重建视图，由当前事实、受校验摘要和近期完整交互组成。

摘要负责帮助模型记忆，不负责决定任务完成或授权。模型写“测试通过”不能创建证据，写“进程已结束”也不能解除真实资源的未知状态。

## 压缩发生在请求冻结之前

Runtime 先结算原工具结果，再构造和测量实际发送视图。需要压缩时，只选择最旧、已闭合的完整交互前缀，工具调用与结果不会拆开。当前事实、有效指令和新纠正保持独立。

摘要生成器只提出候选。Runtime 负责调用意图、预算、返回用量、格式及来源校验、收益检查和原子生效。历史不被摘要覆盖。供应商原生尾部保持原顺序，加密 reasoning 不参与语义摘要。

摘要请求也受容量限制；过大历史分批处理。固定部分或不可拆交互本身超限时停止，不删除约束来满足长度。字符容量与 token 预算是不同单位，费用以真实用量记录。

## 恢复先分类，再继续

Recover 迁移、核对、规范化并记录恢复报告，不执行模型或业务工具。Resume 只在允许的恢复点进入既有推进链。准备中断、模型响应已保存、模型用量未知、工具副作用未知，使用不同规则。

默认 Manual 仅分类。Safe 是显式启用的有限自动续跑，仍受 lease、恢复令牌、权限和预算约束。扫描器、HTTP、资源唤醒和父子内部提交共用这些门禁，不各自解释任务状态。

重启不会恢复 OS 句柄。旧进程意图可找回归属，可信结果可核对，但不会凭旧 PID 接管、杀死或重启。确认进程消失与确认文件副作用不存在是两件事。

## 成本与原文可追溯

业务和摘要共用调用账本。坏摘要也保留费用；可能已发送但未落盘的调用保留未知状态，不免费重试。可信费用核对不伪造收到过模型响应。子任务的费用随既有结算汇总，后补费用只结算差额。

原历史有独立的有界查询。历史分支从指定 Response 的原文边界创建新任务，不复用之后的摘要、约束、资源或预算。检查点升级提供显式读取迁移和备份，不承诺旧二进制理解新执行事实。
